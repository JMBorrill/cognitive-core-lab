# Cognitive Core Lab

**Does specialised fine-tuning improve the tool selection and multi-step orchestration of a 0.5B open-weight model, and does the source of the training signal matter?**

One fixed foundation checkpoint (`Qwen/Qwen2.5-0.5B-Instruct`), four configurations, identical held-out tasks:

| | configuration | weights changed? | training signal |
|---|---|---|---|
| **A** | unmodified baseline (+ a few-shot-prompt variant, A⁺) | no | — |
| **B** | teacher-distilled LoRA | yes (LoRA r=16) | demonstrations generated by a stronger teacher (Qwen3.5-4B), kept only if they pass deterministic execution checks |
| **C** | independently supervised LoRA | yes (LoRA r=16) | trajectories from a programmatic oracle over the task graph, executed and validated the same way |
| **D** | combined LoRA | yes (LoRA r=16) | B ∪ C, either mixed (D) or sequential B→C (D′) |

B is *sequence-level distillation through data*: the teacher's decisions reach the student only as
training text. Every trained configuration modifies weights through LoRA. A⁺ shows how much prompting
alone achieves without any weight change.

Results, methodology and limitations are in **[docs/REPORT.md](docs/REPORT.md)**. Auto-generated
tables are in [results/tables.md](results/tables.md), and the completion matrix is in
[docs/COMPLETION.md](docs/COMPLETION.md).

## Study 02

Study 01 leaves a gap: 86–91% on familiar templates, 30–36% on unseen ones. Study 02 asks what closes
it, and whether the model can close it through verified self-practice. Experiments 0 (bridge to a
PyTorch/CUDA stack) and 1 (diversity dose-response) have been run; results and the recommendation on
Experiment 2 are in **[docs/study02/REPORT_E0_E1.md](docs/study02/REPORT_E0_E1.md)**.

| | result |
|---|---|
| Experiment 0 | the PyTorch port reproduces Study 01 (B and C within 2.3 points on `eval_id` and `eval_ood`); the gap survives conventional LoRA settings |
| Experiment 1, 0.5B | held-out compositions: 18.9% with 25 training families, 37.7% with 1,600, at the same 3,200 episodes (+18.9 points [15.7, 22.2]) |
| Experiment 1, 1.5B | 50.0% and 76.9% (+26.9 points [22.2, 31.4]) |
| reading | diversity of practised structure closes the gap to unpractised compositions; the 0.5B student is then limited by depth |
| recommendation | Experiment 2 on the 1.5B student, after making rollouts cheaper and re-costing |
| compute | 50.37 USD of a 60 USD cap |


## Layout

```
ccl/                    research framework (pure Python + MLX)
  tools.py              typed tool specs, argument validation, deterministic simulators, fault injection
  tasks.py              seeded worlds, 44 scenario templates, gold dependency graphs, splits, leakage audit
  runtime.py            orchestration loop: prompts, action parsing, permissions, approval, limits, traces
  oracle.py             programmatic policy (source of config-C data; validator ceiling)
  evaluate.py           executable validator + per-episode metrics
  models.py             MLX inference backend (batched)
  train.py              resumable LoRA trainer (deterministic batches, checkpoints, sequential stages)
  data.py               episodes -> SFT rows, rejection criteria
  stats.py              bootstrap / hierarchical-bootstrap CIs, paired tests
scripts/
  build_datasets.py     task pools, eval splits, oracle SFT data, leakage audit  -> data/v1
  distill.py            teacher demonstrations with rejection sampling            -> data/v1/teacher
  make_variants.py      budget-matched training sets and train configs           -> configs/train
  run_queue.py          every training + evaluation run, in priority order (resumable)
  evaluate.py           evaluate one configuration                               -> results/runs/<name>
  analyze.py            aggregate, CIs, comparisons, ablations                    -> results/summary.json, tables.md
  agent.py              interactive agent runtime (terminal approval prompts)
  serve.py              local inference server for the showcase's live mode
  export_web.py         publish real run artifacts to web/public/data
configs/                model registry and training configs
data/v1/                versioned tasks and SFT data (hashes in manifest.json)
results/                per-run metrics and aggregated results
archive/                failed training configurations, preserved with loss curves (not used in comparisons)
experiments/            LR pilot and LoRA stability study (pre-registered PLAN.md in each)
web/                    Next.js research showcase (replay + live modes)
tests/                  pytest suite
docs/                   report, model selection, completion matrix, case study, CV summary
```

## Reproduce

Requirements: Apple Silicon Mac (tested on M4, 16 GB), Python 3.11, `uv`, Node 22 (showcase only).

```bash
git clone https://github.com/JMBorrill/cognitive-core-lab.git && cd cognitive-core-lab
uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python -r requirements.lock
# weights (pinned revisions; not committed)
.venv/bin/hf download Qwen/Qwen2.5-0.5B-Instruct --revision 7ae557604adf --local-dir models/Qwen2.5-0.5B-Instruct
.venv/bin/hf download mlx-community/Qwen3.5-4B-MLX-4bit --revision 32f3e8ecf654 --local-dir models/Qwen3.5-4B-MLX-4bit

.venv/bin/python -m pytest -q                    # unit tests (+ slow resume test if weights present)
.venv/bin/python scripts/build_datasets.py       # ~3 s; reproduces data/v1 byte-for-byte (check manifest hashes)
.venv/bin/python scripts/distill.py --n 1600     # teacher data (~6 h on an M4)
.venv/bin/python scripts/make_variants.py
.venv/bin/python scripts/run_queue.py            # all training + evaluation (see docs/REPORT.md for timings)
.venv/bin/python scripts/analyze.py && .venv/bin/python scripts/export_web.py
```

Interactive runtime and showcase:

```bash
.venv/bin/python scripts/agent.py --config B --task-split eval_ood --index 3   # asks you to approve consequential calls
.venv/bin/python scripts/serve.py                                              # live-inference API on 127.0.0.1:8765
cd web && npm ci && npm run dev                                                 # http://localhost:3000
```
